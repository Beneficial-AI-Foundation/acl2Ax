Embedding decisions, general

Every deviation from the ACL2 source in the Lean axioms is listed here or under its element.

General decisions

  1. The embedding is shallow. Each ACL2 theorem or lemma becomes a Lean proposition over Lean types, not over a deep syntax of ACL2 terms.
  2. Every ACL2 number is a Rat. Integer arguments are tested with integerp, which is den = 1.
  3. ACL2 truth values become Lean Prop. The connectives implies, and, or, not and equal become the corresponding Lean connectives.
  4. ACL2 primitives and definitions used in the books are interpreted by Lean functions, listed in the interpretation table. A definition of a book is a Lean def with the ACL2 name in guillemets.
  5. Quantified variables range over Rat or List Rat, not over all ACL2 objects. A theorem with no hypothesis therefore holds in Lean only for rational arguments.
  6. Support definitions live in Lean/ACL2/Base.lean, outside the mirror of the books directory tree.
  7. Hyphens in ACL2 names are kept with Lean guillemets, for example «abs-*».
  8. Each ACL2 theorem is an axiom. The :rule-classes, hints and proofs are not represented.
  9. A module does not import the modules of a local include-book. Non-local includes are imported when their module exists.
  10. A recursive ACL2 definition is a Lean def on Rat, with termination_by on a natural measure. An integer argument is a Rat that satisfies integerp, and the measure is taken from its numerator, so no Int helper is used.
  11. Local theorems and lemmas are axioms too.
  12. ACL2 complex rationals are the Lean type CRat, pairs of Rat with the field operations. A real Rat embeds in CRat with imaginary part 0. Theorems over the reals keep Rat, and theorems over numbers that may be complex use CRat.
  13. The order < on CRat is the lexicographic order of completion-of-< (axioms.lisp, lines 25364 to 25374): x < y holds when realpart x < realpart y, or when the real parts are equal and imagpart x < imagpart y. On real arguments it coincides with the order on Rat.
  14. No Mathlib dependency is used. The CRat type is defined in core Lean, so the shallow embedding needs no require.
  15. Unconstrained ACL2 variables of the cancel-terms-helper book range over CRat. A variable under real/rationalp ranges over Rat, and is coerced to CRat with ↑ when used with complex values.
  16. real/rationalp of a complex rational is true exactly when its imaginary part is 0, because (complex x 0) is the rational x.
  17. A cond with no true clause returns False, as ACL2 returns nil.
  18. helper-9 in the #| |# block at the end of cancel-terms-helper.lisp is a comment, and no axiom is written for it.
  19. ACL2 <= on complex rationals is (not (< y x)), the definition of <=? in axioms.lisp (lines 11614 to 11618). It is the Lean predicate acl2le. On real arguments it coincides with ≤ on Rat.
  20. A variable name that contains +, such as y+, is not a Lean identifier. It is renamed yp in the module. The renaming does not change the statement.
  21. Theorems of non-linear.lisp that state the property for real variables use Rat, and those that state it for numbers that may be complex use CRat.
  22. encapsulate is transparent. The theorems inside it are axioms of the module, and the local ones are included (decision 11). The statements of basic-arithmetic-helper.lisp range over CRat, because ACL2 numbers there include complex values, and (/ x) is CRat.inv x.
  23. quotep and syntaxp hypotheses are represented as always-inhabited types, quotepC x : Type := PUnit and syntaxpW : Type := PUnit. A hypothesis of this type imposes no condition, so an axiom with such a hypothesis is stated without a condition. The representation of quotep and syntaxp is DEFERRED: the user will decide how to represent them properly, for example in the deep embedding. Until then this is a deviation, because the ACL2 statements are conditional on properties of all objects.
  24. numerator on a complex rational is numeratorC. It is the numerator of the real part when the imaginary part is 0, and 0 otherwise, as completion-of-numerator (axioms.lisp, line 25668) states.
  25. syntaxp hypotheses are kept as syntaxpW (decision 25). (syntaxp form) expands to (and form t) (axioms.lisp, line 4558). The representation is deferred with decision 25.
  26. The macro fc in expt.lisp (line 15) is the identity, (defmacro fc (x) x). Each (fc e) is written as e.
  27. expt on complex rationals is exptC r i, with a rational exponent. It follows expt in axioms.lisp (line 9073): exptCInt for an integer exponent, and 1 for a non-integer exponent. The helpers zipR, ifixR and integerpC follow zip, ifix and integerp on complex values. expt on rationals keeps its earlier definition in Base.lean.
  28. Visibility follows ACL2. Each module uses the Lean module system. A non-local include-book is a public import, so its exported names reach the importers, as in ACL2. A local include-book is a plain import, which the module can use in its own declarations but does not re-export. An exported axiom is public axiom. A local axiom is private axiom, which is usable in the module and invisible to importers. ACL2.Base is a public import, and its declarations are public. Local includes are imported only when their module exists. Until then the module records them as pending in a comment. Tests with a scratch project confirmed each of these visibility rules.
  29. The modules cancel-terms-helper, non-linear, basic-arithmetic-helper, basic-arithmetic and expt were generated before decision 30. Their local includes are pending (the comment at the top of each module lists them). Their local imports must be added once those modules exist. The order file ORDER.txt now includes local edges, so these books come after their local dependencies.
  30. Each book's declarations live in the namespace ACL2.<book path>, for example ACL2.«arithmetic-2».pass1.«basic-arithmetic». A local include can bring in public names that share an ACL2 name with the book's own axioms (for example equal-/ in basic-arithmetic-helper and basic-arithmetic). The book namespace keeps the two apart, as the book namespaces of ACL2 do. The shared Base.lean stays in namespace ACL2.
  31. The local includes that exist are now imported: basic-arithmetic imports basic-arithmetic-helper, non-linear imports cancel-terms-helper, and expt imports basic-arithmetic. Pending local includes remain: ../pass1/top for cancel-terms-helper and non-linear, and inequalities, prefer-times and expt-helper for expt. Decision 31 still lists the modules generated before decision 30.
  32. inequalities.lisp is generated after basic-arithmetic, which it includes locally. Its local include is imported. Its iff-equal is a local theorem and is private. The fc macro is inlined (decision 28). All variables are real, so they range over Rat.
  33. Every module depends only on modules that exist. scripts/check_deps.py checks this: each include of the book must be an imported module, and each module must exist. A module with a missing dependency is moved to staged/, outside Lean/, and its manifest status says what it waits for. Staged modules are regenerated once their dependencies exist. Currently staged: cancel-terms-helper and non-linear (waiting for arithmetic-2/pass1/top), and expt (waiting for expt-helper and prefer-times). The import of inequalities was added to expt.
  34. prefer-times.lisp is generated after basic-arithmetic and inequalities, which it includes locally, and both are imported. The equalities over all numbers use CRat and CRat.inv, and the < normalizations over reals use Rat and ⁻¹. Its local theorems iff-equal, times-one and times-minus-one are private.
  35. The local defun Math-induction-start-at-k (expt-helper.lisp, line 22) is an induction scheme used only in hints. It is not a theorem, and no statement uses it, so it is not generated. The local theorem justify-induction is private.
  36. expt.lisp is restored from staged/ once its local dependencies exist: expt-helper and prefer-times are generated. Its imports are basic-arithmetic, inequalities, prefer-times and expt-helper, all plain imports.
  37. mini-theories.lisp: its rule-set forms are not generated (decision 40). Its local lemma Uniqueness-of-*-inverses-lemma-2 is private. Its local includes basic-arithmetic, inequalities, prefer-times and expt are imported.
  38. A function defined by a book (defun) is an opaque constant with its type signature and no body, for example opaque nonneg-int-gcd : Rat → Rat → Rat. The axioms about it are stated, not proved. Its name and namespace follow the same rules as the axioms (decisions 30 and 32), and its uses in statements refer to the constant. Functions of Lean/ACL2/Base.lean keep their interpretations, because they give the ACL2 primitives their meaning. Decision 37 is revised: the local defun Math-induction-start-at-k is generated as an opaque signature, with result type Prop.
  39. denominator on a complex rational is denominatorC: the denominator of the real part when the imaginary part is 0, and 1 otherwise (completion-of-denominator, axioms.lisp, line 25561). The system function nonnegative-integer-quotient (axioms.lisp, line 6889) is an opaque signature in Base.lean, as decision 41 gives for book functions.
  40. numerator-and-denominator-helper.lisp: its functions nonneg-int-mod, nonneg-int-gcd, nonneg-int-gcd-multiplier1, nonneg-int-gcd-multiplier2 and the local induct-on-nonneg-int are opaque signatures (decisions 37 and 41). It has no local includes that need a Lean import beyond basic-arithmetic, inequalities and prefer-times, which are imported as plain imports. Its statements over the integers use Rat, and Nonneg-int-gcd-numerator-denominator ranges over CRat, because its ACL2 statement has no integer hypothesis.
  41. numerator-and-denominator.lisp: its variables range over CRat, with rationalp as realrationalpC, integerp as integerpC, numerator as numeratorC and denominator as denominatorC (decisions 26 and 42). The local lemmas numerator-integerp-lemma-1 and numerator-integerp-lemma are private. Its local includes are imported as plain imports. Base.lean gains one decidability instance, for realrationalpC, which the if in *-r-denominator-r needs. integerpC needs no instance, because it occurs only in a disjunction.
  42. Decidability of the complex predicates in if expressions. The chosen representation is a computable instance, Decidable (realrationalpC c), defined as c.im = 0 (Base.lean). The alternative is to axiomatize decidability, either as axiom of type ∀ c : CRat, Decidable (realrationalpC c) or through Classical.propDecidable. The two alternatives are logically equivalent to the chosen one, and they do not change any statement. They are not chosen, because they make the if depend on a non-computable choice, which ACL2's real/rationalp test does not have. The alternative is recorded for the user's decision.
  43. pass1/top.lisp has no theorem outside a #| |# block comment. Its module imports its non-local includes as public import, and it has no axioms. Its statements are not generated, because the book has none.
  44. cancel-terms-helper and non-linear are restored from staged/, now that pass1/top exists. Their local imports are plain imports: pass1/top for both, and cancel-terms-helper for non-linear.
  45. Block comments of the ACL2 book (#| |#) are recorded verbatim as Lean -- comments at the end of the module, before the namespace closes. They state no axiom. This keeps the removed material, such as the commented-out theorems of pass1/top, visible next to the module.
  46. Alists. An ACL2 alist is a list of pairs, the key as the first component and the value as the second. The Lean type is AList α β := List (α × β) (ACL2.Base). The predicate alistp (axioms.lisp, line 2515) holds of every element of this type, because each element is a pair, so alistp is True on AList. assoc-equal is assocEqual, which returns the first pair with the given key, or none for nil. Keys and values are type parameters, not Rat, because ACL2 objects are untyped (a deviation from the shallow Rat domain, recorded here). The alist is not a Finmap, because alistp does not require unique keys. The finite-map view is the first-match lookup, and no axiom uses a Finmap.
  47. Shared primitives of ACL2.Base, merged from the pilot fragments. There is one symbol type, ACLSymbol, a structure with the symbol-name as field name (axioms.lisp, lines 5615 to 5697). memberSymbolName is member-symbol-name (axioms.lisp, line 5717). trueListp is True, because every Lean list is a true list. arglistp is an opaque signature, because it is defined in the ACL2 system (basis-a.lisp, line 856) and not in a book. stringp is True on String, and length on a string is its character count. char returns Option Char (deviation D1: nil for an index out of range, so the value may be nil). characterp takes Option Char, true for some (deviation D1). code-char is total, Char.ofNat, so for a code outside the range of ACL2 characters it differs from ACL2 (deviation D2, not resolved by the user). char-code is the code of the character as a rational.
  48. Why characterp takes Option Char. ACL2 characterp is a predicate on every object, and char returns nil for an index out of range. The statement characterp-of-char, (characterp (char s n)) equivalent to (stringp s ∧ nfix n < length s), requires characterp to be false on that nil. A characterp on Char alone has no value for char to return, so Option Char is the carrier, with none for nil. This is the consequence of deviation D1 in decision 50, and it is open for the user's decision together with D1.
  49. Batch primitives merged into ACL2.Base. natp, realfix, rfix, stringListp, addToSetEqual, consp, function-symbolp and arity (opaque, basis-b.lisp line 2255), symbolp (abbrev, True, deviation D3) and primitivep (opaque) are declared once in Base.lean. The module files of the batch keep only their own axioms. arity-iff ranges over symbols, so the cons case is excluded (deviation). rfix and realfix axioms sit in their book namespaces, as decision 32 requires. The arithmetic/real-listp book has no axioms, because both theorems sit under #+:non-standard-analysis (decision 12).
  50. Rule-set bookkeeping forms are not generated. These are in-theory, deftheory, theory-invariant, and the enable and disable forms they contain. They select which rewrite rules the ACL2 prover uses, and they state no theorem about values. Each theorem they refer to is still generated as its own axiom.
  51. A reader conditional that excludes a form in standard ACL2 excludes its axiom, and the exclusion is recorded.

Excluded books: metaprogramming

Interpretation rows: std/system/dumb-negate-lit and std/system/implicate are excluded as metaprogramming, with status excluded: metaprogramming in manifest.json. Both books state properties of ACL2 terms as data (pseudo-termp, dumb-negate-lit, implicate). No module is written.
