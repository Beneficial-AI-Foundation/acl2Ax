Embedding rules 18 general decisions

These rules apply to every book. Each element of a book may add its own decision, shown on its blueprint page.

  1. The embedding is shallow. Each ACL2 theorem or lemma becomes a Lean proposition over Lean types, not over a deep syntax of ACL2 terms.
  2. Every ACL2 number is a Rat. Integer arguments are tested with integerp, which is den = 1.
  3. ACL2 truth values become Lean Prop. The connectives implies, and, or, not and equal become the corresponding Lean connectives.
  4. ACL2 primitives and definitions used in the books are interpreted by Lean functions, listed in the interpretation table. A definition of a book is a Lean def with the ACL2 name in guillemets.
  5. Quantified variables range over Rat or List Rat, not over all ACL2 objects. A theorem with no hypothesis therefore holds in Lean only for rational arguments.
  6. Support definitions live in Lean/ACL2/Base.lean, outside the mirror of the books directory tree.
  7. Hyphens in ACL2 names are kept with Lean guillemets, for example «abs-*».
  8. Each ACL2 theorem is an axiom. The :rule-classes, hints and proofs are not represented.
  9. A module does not import the modules of a local include-book. Non-local includes are imported when their module exists.
  10. A recursive ACL2 definition is a Lean def on Rat, with termination_by on a natural measure. An integer argument is a Rat that satisfies integerp, and the measure is taken from its numerator, so no Int helper is used.
  11. Local theorems and lemmas are axioms too.
  12. Visibility follows ACL2. Each module uses the Lean module system. A non-local include-book is a public import, so its exported names reach the importers, as in ACL2. A local include-book is a plain import, which the module can use in its own declarations but does not re-export. An exported axiom is public axiom. A local axiom is private axiom, which is usable in the module and invisible to importers. ACL2.Base is a public import, and its declarations are public. Local includes are imported only when their module exists. Until then the module records them as pending in a comment. Tests with a scratch project confirmed each of these visibility rules.
  13. Each book's declarations live in the namespace ACL2.<book path>, for example ACL2.«arithmetic-2».pass1.«basic-arithmetic». A local include can bring in public names that share an ACL2 name with the book's own axioms (for example equal-/ in basic-arithmetic-helper and basic-arithmetic). The book namespace keeps the two apart, as the book namespaces of ACL2 do. The shared Base.lean stays in namespace ACL2.
  14. Every module depends only on modules that exist. scripts/check_deps.py checks this: each include of the book must be an imported module, and each module must exist. A module with a missing dependency is moved to staged/, outside Lean/, and its manifest status says what it waits for. Staged modules are regenerated once their dependencies exist. Currently staged: cancel-terms-helper and non-linear (waiting for arithmetic-2/pass1/top), and expt (waiting for expt-helper and prefer-times). The import of inequalities was added to expt.
  15. A function defined by a book (defun) is an opaque constant with its type signature and no body, for example opaque nonneg-int-gcd : Rat → Rat → Rat. The axioms about it are stated, not proved. Its name and namespace follow the same rules as the axioms (decisions 30 and 32), and its uses in statements refer to the constant. Functions of Lean/ACL2/Base.lean keep their interpretations, because they give the ACL2 primitives their meaning. Decision 37 is revised: the local defun Math-induction-start-at-k is generated as an opaque signature, with result type Prop.
  16. Block comments of the ACL2 book (#| |#) are recorded verbatim as Lean -- comments at the end of the module, before the namespace closes. They state no axiom. This keeps the removed material, such as the commented-out theorems of pass1/top, visible next to the module.
  17. Rule-set bookkeeping forms are not generated. These are in-theory, deftheory, theory-invariant, and the enable and disable forms they contain. They select which rewrite rules the ACL2 prover uses, and they state no theorem about values. Each theorem they refer to is still generated as its own axiom.
  18. A reader conditional that excludes a form in standard ACL2 excludes its axiom, and the exclusion is recorded.
