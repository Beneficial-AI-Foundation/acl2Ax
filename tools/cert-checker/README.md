# cert-checker

An integrity checker for ACL2 `.cert` files. It reads a `.cert` and the `.lisp` file
of the same book, and it reports whether the hashes and the lengths and write dates
that the cert records agree with the files on disk. It also checks each recorded
dependency against its own `.cert` and `.lisp`.

It does not replay proofs. It does not evaluate the ACL2 logic and does not check guards.
Its output says so on every run.

## Status

| Part | Status |
| --- | --- |
| Checker core (`cert_check.c`) | Built and run natively with Apple clang |
| Native driver (`native_main.c`) | Built and run |
| Node harness (`check.js`) | Syntax checked with `node --check`. Not run, because there is no wasm file |
| wasm build (`build_wasm.sh`) | Not run. The installed clang has no wasm32 backend, and `wasm-ld` is not installed |

The wasm artifact `cert_check.wasm` is not in this directory. Building it needs an LLVM
toolchain with the wasm32 backend and `wasm-ld`.

## Usage

Native build (tested):

```
clang -std=c99 -O2 -o cert_check_native native_main.c cert_check.c
./cert_check_native [--books-dir DIR] FILE.cert FILE.lisp
```

Node harness (requires `cert_check.wasm` in the same directory):

```
node check.js [--books-dir DIR] FILE.cert FILE.lisp
```

`--books-dir` is the ACL2 `books` directory. Recorded dependencies carry names such as
`(:SYSTEM . "arithmetic/top.lisp")`, which resolve against that directory. When the
option is omitted, both drivers use the nearest ancestor directory named `books` of the
cert path.

Exit status: 0 for PASS, 1 for FAIL, 2 for UNVERIFIED or a usage error.

## What is checked

The format is ACL2 8.7 serialized V3 (`serialize-raw.lisp`). The cert is a sequence of
`#Z` objects. Forms are, in order: `(in-package "ACL2")`, the version string, the
`:BEGIN-PORTCULLIS-CMDS` block, `:EXPANSION-ALIST` and `:CERT-DATA` when present, the
pre-alist, the post-alist, and the cert-hash. The decoder and the layout cite the source
in comments in `cert_check.c`.

Two hash modes exist, selected by ACL2's `book-hash-alistp` state global when the book
was certified.

Alist mode (the mode of the books in the ACL2 8.7 tree, for example `arithmetic/abs.cert`):

- The cert-hash is `:TRIVIAL-BOOK-HASH`, so the cert content is not hashed and the
  checker reports "cert checksum NOT RECORDED".
- The own entry of the post-alist records `(:BOOK-LENGTH . n)` and
  `(:BOOK-WRITE-DATE . d)` for the `.lisp` file. The checker compares `n` with the file
  size and `d` with the file write date (universal time, seconds since 1900).
- Each recorded dependency is compared the same way with its `.lisp` file. Its own
  `.cert` must record the same length and write date, and its `.lisp` must match.

Checksum mode (an integer cert-hash):

- The cert checksum is recomputed as `check-sum-obj` over the cmds, the pre-alist, the
  post-alist, the expansion alist, and the cert-data.
- The own-entry book-hash is recomputed as `check-sum-obj` over the cmds, the expansion
  alist, the events read from the `.lisp` file, and the cert-data.
- Each recorded dependency's stored checksum must equal its own-entry checksum in its
  `.cert`, and its `.lisp` must reproduce that checksum.

The checksum functions are ported from `basis-b.lisp` (`fchecksum-obj`, `fchecksum-atom`,
`fchecksum-string1`, `fchecksum-natural`, `times-mod-m31`). The CL import list used to
read the events is in `cl_symbols.h`, generated by `gen_cl_symbols.py` from
`axioms.lisp` (`*common-lisp-symbols-from-main-lisp-package*`, 978 names).

## What is not checked

- Proofs. No event is replayed, and no `:DOC` or `:RUNE` is evaluated.
- The ACL2 logic and the guards.
- Alist mode content. Its hash is a length and a write date, so a change that keeps the
  length and the write date of a `.lisp` file is not detected. The checker does not
  report it.
- Comments and whitespace in checksum mode. The events hash reads the forms, so a
  comment-only edit does not change it.
- Recorded books beyond one level. Each direct or recorded dependency is checked against
  its own files, and the dependencies of those dependencies are not followed.
- Books that the post-alist does not record, and the portcullis commands beyond their
  presence in the cert.

## Limits of the decoder and reader

- Refused with an UNVERIFIED reason: complex numbers in a cert, integers over 63 bits,
  V1 and V2 serialized objects, source `#` reader macros other than `#\` and `#'`,
  backquote, and non-ACL2 packages other than KEYWORD and COMMON-LISP in the events.
- In the tree, `misc/check-acl2-exports.cert` fails with "serialized string runs past the
  end of the data", and `centaur/bitops/fast-logext.cert` fails with "natural exceeds
  63 bits". Neither is checked.

## Tests

Run on the ACL2 8.7 tree, with the native driver:

- `arithmetic/abs.cert` with `arithmetic/abs.lisp`: PASS, exit 0.
- A copy of `abs.lisp` with one character changed (`(<= 0 x)` to `(<= 1 x)`, same length):
  FAIL, exit 1, write date mismatch.
- The same copy with its modification time restored: PASS, exit 0. This is the limit
  described above.
- A copy one byte longer: FAIL, exit 1, length mismatch.

The checksum path has not been run against an ACL2-produced checksum-mode cert. None of the
1452 `.cert` files in the tree uses checksum mode, and a certification run for a test
book was not allowed in this session.
